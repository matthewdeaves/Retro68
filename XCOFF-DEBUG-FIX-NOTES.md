# XCOFF `.debug` section-size assertion — root cause + candidate fix

**Status: UNVERIFIED candidate.** Reasoned from source; not yet built or run.
Do not merge to `master` until built and tested (see "Verification" below).

## Symptom

Linking a C++ translation unit for `powerpc-apple-macos` aborts:

```
ld: BFD (GNU Binutils) 2.39 assertion fail .../bfd/xcofflink.c:7571
collect2: error: ld returned 1 exit status
```

Reproduces on `AutomatedTests/PascalTrapCPP.cc` (generated by
`configure_file(PascalTrap.c PascalTrapCPP.cc)` in `AutomatedTests/CMakeLists.txt`).
The identical source compiled as C (`PascalTrap.c`) links fine.

## Root cause

1. The XCOFF linker merges every input `.debug` (stabs) section into one
   synthesized `.debug` section + a string table (`debug_strtab`). Strings are
   only ever added in `bfd_xcoff_build_dynamic_sections`
   (`xcofflink.c:4239`); its size is therefore final after that function.
2. That function sets `debug_section->size = _bfd_stringtab_size(debug_strtab)`
   (`xcofflink.c:4278`) and is called from the linker's **after_allocation**
   hook (`ld/emultempl/aix.em:1164`) — i.e. **after** `lang_size_sections`
   has already finalized output section sizes. Nothing re-lays-out afterward.
3. At allocation time the synthesized `.debug` was still empty, so the `.debug`
   output section (`.debug : { *(.debug) }` in `ld/scripttempl/ppcmacos.sc`)
   was sized 0. The string table is non-empty, so at final-link
   `_bfd_xcoff_bfd_final_link` asserts
   `output_section->size(0) - output_offset(0) >= stringtab_size(N>0)` → abort.

C links because its `.debug` stabs are empty/tiny; C++ emits enough
(mangled names) to make `N > 0`. AIX never trips it because its toolchain
does not emit COFF stabs into `.debug` — this is a latent upstream binutils
bug that the `ppcmacos` target is the first to exercise.

This is **upstream** (autc04 base + stock binutils 2.39), not a regression in
this fork. `PascalTrapCPP.cc` is upstream's own generated test.

## Candidate fix

`binutils/bfd/xcofflink.c`, in `bfd_xcoff_build_dynamic_sections`: when the
final `.debug` size is known, propagate it to the output section.

```c
asection *dsec = xcoff_hash_table (info)->debug_section;
dsec->size = _bfd_stringtab_size (debug_strtab);
if (dsec->output_section != NULL)
  dsec->output_section->size = dsec->output_offset + dsec->size;
```

`output_section`/`output_offset` are already assigned by allocation time.
`.debug` is the last, non-loadable output section, so growing it cannot shift
any loadable section's VMA. For targets that emit no `.debug` stabs (AIX) this
is a no-op. Lives in the aix template path, so it also covers `aixppc`/`aix5ppc`
— harmless there for the same reason.
